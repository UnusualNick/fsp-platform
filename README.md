# ФСП — ИТ-подбор / спецтрек ФСП, ЛЦТ 2026

Работающий локальный MVP обратного подбора ИТ-специалистов. Работодатель выбирает подтверждённую категорию и отправляет предложение с зарплатой. Контакты кандидат открывает принятием приглашения. Все демопрофили, компании и достижения синтетические.

## Быстрый запуск

Нужен Python 3.12+; основной сервер, SQLite и тестирование используют стандартную библиотеку. Зависимость ReportLab нужна для PDF-профиля.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python server.py --port 8080
```

Откройте http://127.0.0.1:8080. В текущей рабочей сессии демонстрация запущена на http://127.0.0.1:8765. На Windows активация: `.venv\Scripts\activate`.

```sh
docker compose up -d --build --wait
docker compose ps
```

Compose запускает веб-сервис и SQLite в одном контейнере, от непривилегированного пользователя. База сохраняется в именованном томе platform-data; повторный запуск не пересоздаёт демоданные. Healthcheck проверяет HTTP и доступ к SQLite. Если порт занят: `PORT=8081 docker compose up -d --build --wait`. Приложение доступно на http://localhost:8081.

Остановка: `docker compose down` (данные сохраняются). `docker compose down -v` удаляет базу — используйте только для сброса тестового экземпляра. Логи: `docker compose logs --tail=100 platform`.

- Кандидат: `candidate@example.test`.
- Пароль обоих: `DemoPassword42!`.

Сервер по умолчанию создаёт `data/platform.sqlite`, только если база пустая. Для отдельной проверки: `python server.py --port 8081 --db data/separate-demo.sqlite`. Не используйте деморежим для настоящих персональных данных.

## Сквозная демонстрация

1. Зарегистрируйте синтетический аккаунт кандидата, задайте пароль от 12 символов. В деморежиме подтвердите адрес кнопкой «Подтвердить email», затем войдите. В production ссылка отправляется через SMTP.
2. Заполните имя, стек и контакт. Включите согласие на публикацию.
3. Пройдите опрос и тест. Категория появляется только после успешного теста. Провал не присваивает автоматически более низкий грейд.
4. В отдельном браузере или после выхода войдите как работодатель. Выберите ту же специализацию и грейд, введите стек.
5. Откройте объяснение подбора и отправьте приглашение с диапазоном зарплаты.
6. В кабинете кандидата проверьте компанию, условия, зарплату. Примите или отклоните приглашение.
7. В кабинете работодателя статус «Принято» открывает контакт кандидата. До принятия API возвращает 403.
8. Дополнительно покажите публикацию вакансии, самостоятельный отклик с согласием на передачу контактов, профиль без ФСП и экспорт PDF.

## Проверки

```sh
python -m unittest discover -s tests -v
python validate.py
```

26 автоматизированных тестов проверяют бизнес-правила и настоящий HTTP API. `validate.py` воспроизводит синтетический набор, разметку 9 запросов, Precision@1/3, уникальность 900 форм и локальный замер ранжирования. Итоги находятся в `data/validation-results.json`; результаты на синтетике не являются оценкой качества реального найма.

## Архитектура и API

- `web/`: адаптивный клиент HTML/CSS/JS без сборки и внешних ресурсов.
- `server.py`: HTTP, cookie, CSRF, ограничения запросов, PDF.
- `service.py`: регистрация, права, категории, приглашения, вакансии.
- `storage.py`: SQLite, транзакции и внешние ключи.
- `assessment.py`: шаблоны форм и проверка.
- `matching.py`: объяснимое ранжирование без личных характеристик.
- `seed.py`: синтетические сценарии, отдельный демореестр ФСП.
- `docs/openapi.json`: OpenAPI 3.1, запросы, ответы и ошибки всех API. Также доступен `/openapi.json`.

Подробная архитектура, ограничения, интеграция ФСП, процедура валидации и эксплуатация изложены в сопроводительном PDF в комплекте.

## Режим SMTP

Внешнее размещение требует HTTPS reverse proxy и переменных среды `PUBLIC_URL`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM`. Для SMTP-аутентификации дополнительно нужны `SMTP_USER`, `SMTP_PASSWORD`. Не сохраняйте секреты в коде или репозитории.

```sh
python server.py --production --host 0.0.0.0 --port 8080
```

Production-флаг отключает синтетический реестр, демоданные и выдачу email-токенов в ответах, включает Secure cookie. Это технический режим, а не подтверждение готовности к промышленной эксплуатации. До приёма реальных пользователей нужны проверка безопасности, реальные процедуры обработки данных, расширение банка заданий, экспертная калибровка грейдов и интеграция реестра ФСП.

## Границы MVP

Реализованы два кабинета, ручное заполнение профиля, PDF-профиль, подтверждение email, опрос и тест, категория, история тестов, 90-дневный интервал успешных подтверждений, фильтры, объяснение подбора, приглашения и их статусы, контактное согласие, вакансии и отклики. Внешний SMTP предусмотрен, но доставка на настоящую почту не проверялась. Нет импорта PDF-резюме/OCR, реального ФСП API/Keycloak, готового ATS-коннектора и модерации. Короткие адресные задания реализованы в отдельном разделе «Задание недели». Редактирование собственных вакансий и обработка откликов работодателем реализованы. Концепция ATS достаточна для MVP по ответам организаторов; остальные ограничения перечислены отдельно, без общего заявления об их необязательности.

Презентация пока содержит обозначенные поля команды: пользователь ещё не предоставил состав и контакты. Краткий видеообзор реальных экранов приложен отдельно; запись полного сценария ещё нужна. Репозиторий: https://github.com/UnusualNick/fsp-platform — приватный по запросу владельца. Для проверки экспертами его нужно сделать публичным. Внешний URL и подача на платформу пока не выполнены. ## Айдентика и UX

Источник — полный брендбук ФСП: https://disk.yandex.ru/d/nxMN6oQTZ25wZQ. Проверены палитра (стр. 8), JetBrains Mono (стр. 21), TDAText (стр. 22) и паттерны (стр. 24). Рабочий интерфейс использует JetBrains Mono. Палитра: #402FFF, #EC1D35, #1B1C21, #3A3C46, #D9D9D9, #EDEDED; цифровой акцент #0A006B используется при наведении на основные кнопки. Белые поверхности — интерфейсное дополнение. Логотип неизменён. Паттерн экрана входа взят из брендбука без перекрашивания. Отступы 4/8/12/16/24/32 px — интерфейсная шкала, а не требование брендбука.

Рабочая область центрирована и ограничена по ширине. Компактная выдача: аватар, технологии, отметка теста, достижения, шкала соответствия. Точная оценка и объяснение доступны в профиле. Наведение не перекрашивает всю строку. На мобильном экране таблица превращается в карточки.

Фильтры применяются ко всему набору до пагинации: категория, технологии, совпадение всех технологий, имя/текст профиля, минимальный тест и соответствие, подтверждённые достижения ФСП. Есть сортировка, сброс, страницы и размер страницы. Контакты защищены на сервере до согласия кандидата.

## Уточнения организаторов — проверено 11 октября 2026

Реальный API ФСП не предоставляется. Используется локальный мок реестра с проверкой ID, кода и email владельца. Это не реальная верификация Федерацией. Синтетический источник обозначен в UI и PDF-профиле.

Членство в ФСП не хранится и не влияет на подбор. Спортивный разряд не является условием допуска. Баллы ФСП дают только записи с verified=true. Без достижений профиль участвует в подборе по тесту и стеку.

Для сдачи нужен публичный репозиторий, включая SourceCraft. До 11 октября, 23:59 МСК, требуется полное решение первого этапа. Обязательные слайды 7–11 сохраняют дизайн шаблона. На финальной защите — 5 минут выступления и 5 минут вопросов. Серверы организаторы не предоставляют.

Источники и оставшиеся шаги: docs/submission-checklist.txt. Приватный репозиторий создан: https://github.com/UnusualNick/fsp-platform. Публичный доступ и внешний URL ещё не подготовлены. Презентация, PDF-документация и видео в родительской папке показывают предыдущий UI; актуальный исходный код находится здесь и в архиве fsp-platform.zip.

Прочитаны все 17 ответов из официальной таблицы. Категория — специализация и подтверждённый тестом грейд; стаж не заменяет тест. Одна категория достаточна для MVP. Достижения ФСП повышают рейтинг только внутри категории; дисциплины равноправны. Задания под вакансию, ATS и защита от списывания необязательны для MVP. Собственные синтетические данные разрешены. Подробная сверка: docs/organizer-clarifications.md.

`python validate.py` проверяет подбор, разнообразие форм и парное сравнение test–retest: 150 модельных профилей на каждую из девяти категорий, две попытки в старой и новой форме. Отчёт data/validation-results.json содержит согласованность подтверждения грейда, Cohen kappa, корреляцию баллов, пограничную группу и разделяющую силу с исключением измеряемого задания из группирующего балла. Средняя согласованность в модели выросла с 76,4% для шести заданий до 84,3% для 12. Это диагностика при явно заданной независимой модели ответов, а не доказательство психометрической надёжности реального теста.

Новые тесты версии 2026.10.2: 12 заданий, 20 минут, шесть дополнительных блоков основных компетенций с двумя альтернативными сценариями в каждом. Пороги не снижены: 9 правильных ответов для Junior/Middle, 11 для Senior. Старые активные формы проверяются по сохранённым вопросам. Банк требует экспертной калибровки, особенно для Senior; около порогов сохраняется нестабильность.

## Проверка работающего Compose

```sh
docker compose run --rm --no-deps platform python -m unittest discover -s tests -v
docker compose exec -T platform python scripts/smoke.py
```

Smoke-сценарий создаёт синтетическую вакансию и отклик, проверяет приглашение, принятие, открытие контактов, редактирование вакансии, решение по отклику, мок ФСП и PDF. Он допускается только на экземпляре с demo=true. Для проверки сохранности данных после smoke: `docker compose up -d --force-recreate --wait`, затем проверьте вакансию в интерфейсе.

Для публичного репозитория публикуйте содержимое этого каталога как корень проекта. Не включайте SQLite, .env, токены и личные данные; исключения заданы в .gitignore и .dockerignore. Каталог submission-drafts/ в GitHub содержит презентацию, PDF и видео предыдущей версии для доработки; их статус указан в отдельном README. Промежуточные материалы work/ не нужны для запуска и не публикуются.

## Быстрые улучшения и проверка

В кабинете кандидата откройте «Задание недели»: три вопроса по подтверждённой специализации, отправка один раз, разбор и история. Новое задание выдаётся при открытии раздела спустя семь дней; фонового планировщика и email-напоминаний нет. Банк практики отделён от оценочного теста. Это небольшой демонстрационный банк; результат не меняет грейд, рейтинг и не является измерением актуальности компетенций.

В подборе работодателя введите «Нужен middle frontend-разработчик, React и TS», нажмите «Распознать требования», примените предложенную категорию, проверьте фильтры и нажмите «Показать кандидатов». Разбор работает на локальных правилах и словаре; неподдерживаемые формулировки требуют ручного исправления. При неоднозначном грейде система не выбирает его автоматически. Поиск нормализует JS/JavaScript, TS/TypeScript, Postgres/PostgreSQL и другие распространённые варианты; новые навыки вне словаря сопоставляются по полному названию.

Локальная проверка HTTP-чтения: `python scripts/load_readonly.py --base http://127.0.0.1:8081`. Отчёт — `data/http-load.json`: 100 запросов, параллелизм 8, поиск, вакансии и приглашения. Это небольшой smoke-бенчмарк, без проверки конкурентной записи и производственной пропускной способности.
