# ФСП: подбор ИТ-специалистов

Кандидат подтверждает специализацию и грейд тестом. Работодатель находит подходящих специалистов и отправляет приглашение с зарплатой. Контакты открываются после согласия кандидата.

- [Открыть платформу](https://fsp.bobs-ai.ru)
- [API](docs/openapi.json) · [Требования и ответы организаторов](docs/organizer-clarifications.md)
- Спецтрек Федерации спортивного программирования, ЛЦТ 2026.

## Запуск

Нужны Docker с Compose и свободный порт 8080. Из корня репозитория:

```sh
docker compose up -d --build --wait
```

Откройте [localhost:8080](http://localhost:8080). Команда собирает и запускает всё решение: веб-интерфейс, API и SQLite. База хранится в томе `platform-data` и сохраняется после перезапуска. Контейнер работает от непривилегированного пользователя; healthcheck проверяет API и доступ к базе.

Если порт занят: `PORT=8081 docker compose up -d --build --wait`. Логи: `docker compose logs --tail=100 platform`. Остановка: `docker compose down`.

## Вход

На стартовом экране есть кнопки входа в оба кабинета. Также можно войти по email:

| Роль | Email | Пароль |
| --- | --- | --- |
| Работодатель | `employer@example.test` | `DemoPassword42!` |
| Кандидат | `candidate@example.test` | `DemoPassword42!` |

Для привязки записи участника в кабинете кандидата: ID `FSP-DEMO-001`, код `demo-owner-001`. Они относятся к аккаунту `candidate@example.test`.

## Сценарий проверки

1. Войдите как работодатель. Выберите специализацию, грейд и технологии. Условия можно ввести текстом, проверить и перенести в фильтры.
2. Выберите Backend-разработку и Middle, откройте профиль Дмитрия Новикова. В нём показаны результат теста, достижения и объяснение позиции в подборке.
3. Отправьте приглашение с задачами и диапазоном зарплаты.
4. Войдите как кандидат, откройте приглашение и примите его. После этого работодатель увидит контакты.
5. Проверьте второй путь: публикация вакансии, отклик кандидата с согласием на передачу контактов и решение работодателя.

В кабинете кандидата доступны редактирование профиля, управление публикацией, тест, история результатов, задание недели и экспорт PDF. Новый аккаунт подтверждает email кнопкой после регистрации.

Тест содержит 12 заданий на 20 минут. Для Junior и Middle нужны 9 правильных ответов, для Senior 11. После успешного теста повторно подтвердить категорию можно через 90 дней. Неудачная попытка не понижает грейд. Задание недели даёт три вопроса по специализации и сохраняет разбор отдельно от оценки грейда.

В подборе сначала применяется категория, затем считаются баллы: до 60 за технологии, до 30 за тест и до 10 за достижения ФСП. Кандидаты без истории соревнований также участвуют. Работодатель не получает контакты до принятия приглашения или отклика с согласием.

## Устройство

| Файлы | Назначение |
| --- | --- |
| `web/` | HTML, CSS и JavaScript, без сборки и внешних ресурсов |
| `server.py`, `service.py` | HTTP API, регистрация, права, профили, приглашения и вакансии |
| `storage.py` | SQLite, транзакции и внешние ключи |
| `assessment.py`, `question_bank.py` | Формы теста и проверка ответов |
| `matching.py`, `needs.py` | Фильтры, объяснение баллов и разбор требований |
| `practice_bank.py` | Задания недели |
| `seed.py` | Начальные аккаунты, профили и вакансии |

Сессии используют HttpOnly cookie; запись защищена CSRF-токеном и проверкой роли. Согласие на публикацию профиля и передачу контактов проверяется сервером. Контракт OpenAPI доступен также по адресу `/openapi.json`.

Цвета, логотип, паттерн и JetBrains Mono взяты из [брендбука ФСП](https://disk.yandex.ru/d/nxMN6oQTZ25wZQ). Лицензии ресурсов перечислены в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

## Проверки

```sh
docker compose run --rm --no-deps platform python -m unittest discover -s tests -v
docker compose exec -T platform python scripts/smoke.py
```

31 тест проверяет бизнес-правила и HTTP API. Smoke проходит подбор, приглашение, согласие и открытие контактов, вакансии, отклики, привязку участника и PDF. Он создаёт записи и работает только в демонстрационном режиме.

`python validate.py` воспроизводит проверку ранжирования, разнообразия форм и test-retest. Отчёт хранится в `data/validation-results.json`; условия расчёта описаны в [уточнениях организаторов](docs/organizer-clarifications.md#валидация-теста). Проверка HTTP-чтения: `python scripts/load_readonly.py --base http://127.0.0.1:8080`.

Для запуска без Docker нужны Python 3.12+ и зависимости из `requirements.txt`: установите их в виртуальное окружение и выполните `python server.py --port 8080`.

## Данные и ограничения

При первом запуске создаются 36 вымышленных профилей и локальный реестр достижений; действующий API ФСП не подключён. Результаты валидации рассчитаны на модельных данных, а качество найма и точность грейдов требуют проверки на реальных кандидатах. Разбор требований использует словарь и правила; распознанные условия можно исправить. Задание недели выдаётся при открытии раздела, без фоновой рассылки. Импорт резюме, ATS-коннектор, Keycloak и модерация пока отсутствуют.

Для реальных пользователей требуется настроить HTTPS, SMTP, интеграцию ФСП и обработку персональных данных, проверить безопасность и откалибровать банк заданий. Режим `--production` не создаёт начальные аккаунты, отключает локальный реестр и выдачу email-токенов в ответах, включает Secure cookie. Настройки почты передаются через `PUBLIC_URL`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM` и при необходимости `SMTP_USER`, `SMTP_PASSWORD`. Доставка через внешний SMTP пока не проверена.
