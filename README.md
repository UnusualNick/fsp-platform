## Запуск

Нужны Docker с Compose и свободный порт 8080. В корне репозитория выполните:

```sh
docker compose up -d --build --wait
```

Откройте [localhost:8080](http://localhost:8080). Команда собирает и запускает всё решение: веб-интерфейс, API и SQLite. База хранится в томе `platform-data` и сохраняется после перезапуска. Контейнер работает без root, healthcheck проверяет API и базу

Если порт занят: `PORT=8081 docker compose up -d --build --wait`

Логи: `docker compose logs --tail=100 platform`

Остановка: `docker compose down`

Для привязки участника к аккаунту `candidate@example.test` используйте ID `FSP-DEMO-001` и код `demo-owner-001`

## Сценарий проверки

1. Войдите как работодатель. Выберите специализацию, грейд и технологии. Условия можно ввести текстом, проверить и перенести в фильтры
2. Выберите Backend-разработку и Middle, откройте профиль Дмитрия Новикова. В нём видны результат теста, достижения и объяснение позиции в подборке
3. Отправьте приглашение с задачами и диапазоном зарплаты
4. Войдите как кандидат и примите приглашение. Работодатель увидит контакты
5. Проверьте второй путь: публикация вакансии, отклик с согласием на передачу контактов и решение работодателя

Кандидат указывает роли, стаж и навыки командной работы, публикует профиль, проходит тест, смотрит историю результатов, выполняет задание недели и скачивает PDF. После регистрации email подтверждается кнопкой

В тесте 12 заданий на 20 минут. Для Junior и Middle нужны 9 верных ответов, для Senior 11. После успеха повторное подтверждение доступно через 90 дней. Неудачная попытка не понижает грейд. Задание недели содержит три вопроса по специализации, разбор сохраняется отдельно от оценки грейда

Подбор сначала отбирает по категории, затем начисляет до 60 баллов за технологии, до 30 за тест и до 10 за достижения ФСП. История соревнований необязательна. Контакты доступны после принятия приглашения или отклика с согласием

## Устройство

| Файлы | Назначение |
| --- | --- |
| `web/` | HTML, CSS и JavaScript без сборки и внешних ресурсов |
| `server.py`, `service.py` | HTTP API, регистрация, права, профили, приглашения и вакансии |
| `storage.py` | SQLite, транзакции и внешние ключи |
| `assessment.py`, `question_bank.py` | Формы теста и проверка ответов |
| `matching.py`, `needs.py` | Фильтры, объяснение баллов и разбор требований |
| `practice_bank.py` | Задания недели |
| `seed.py` | Начальные аккаунты, профили и вакансии |

Сессии используют HttpOnly cookie. Сервер защищает запись CSRF-токеном, проверяет роль и согласия на публикацию профиля и передачу контактов. OpenAPI доступен также по адресу `/openapi.json`

Цвета, логотип, паттерн и JetBrains Mono взяты из [брендбука ФСП](https://disk.yandex.ru/d/nxMN6oQTZ25wZQ). Лицензии ресурсов указаны в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)

## Проверки

```sh
docker compose run --rm --no-deps platform python -m unittest discover -s tests -v
docker compose exec -T platform python scripts/smoke.py
```

39 тестов проверяют бизнес-правила и HTTP API. Smoke проходит подбор, приглашение, согласие и открытие контактов, вакансии, отклики, привязку участника и PDF. Он создаёт записи и работает только в демонстрационном режиме

`python validate.py` проверяет ранжирование, разнообразие форм и test-retest. Результат записывается в `data/validation-results.json`, условия расчёта описаны в [уточнениях организаторов](docs/organizer-clarifications.md#валидация-теста)

Проверка HTTP-чтения: `python scripts/load_readonly.py --base http://127.0.0.1:8080`

Без Docker: установите Python 3.12+ и зависимости из `requirements.txt` в виртуальное окружение, выполните `python server.py --port 8080`

## Данные и ограничения

При первом запуске создаются 36 вымышленных профилей и локальный реестр достижений, API ФСП не подключён. Валидация выполнена на модельных данных. Качество найма и точность грейдов требуют проверки на реальных кандидатах

Разбор требований работает по словарю и правилам, результат можно исправить. Задание недели выдаётся при открытии раздела, без фоновой рассылки. Импорт резюме, ATS-коннектор, Keycloak и модерация пока отсутствуют

Для реальных пользователей нужно настроить HTTPS, SMTP, интеграцию ФСП и обработку персональных данных, проверить безопасность и откалибровать банк заданий. Режим `--production` не создаёт начальные аккаунты, отключает локальный реестр и email-токены в ответах, включает Secure cookie. Почта настраивается через `PUBLIC_URL`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM`, при необходимости `SMTP_USER` и `SMTP_PASSWORD`. Доставка через внешний SMTP пока не проверена
