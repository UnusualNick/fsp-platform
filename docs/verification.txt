Проверка 11 октября 2026 (МСК).

Docker Compose собран и запущен через docker compose up -d --build --wait.
Локальный порт 8080 занят другим сервисом; экземпляр запущен с PORT=8081.
Статус контейнера: healthy. /api/health проверяет HTTP и доступ к базе SQLite.
26 автоматизированных тестов прошли внутри Docker (Python 3.12).
После чтения официального XLSX добавлена и выполнена в Docker test–retest симуляция: 1350 синтетических профилей, 2700 попыток, 9 категорий. Согласованность подтверждения 69,3–86,7%; это диагностика чувствительности к порогу, не подтверждение психометрической надёжности. Повторный запуск всех 26 тестов успешен.
Последующее улучшение 11.10: форма 2026.10.2 с 12 заданиями, шестью дополнительными блоками компетенций; процентные пороги прежние. Парное сравнение на одинаковых профилях/seed: согласованность 76,4% → 84,3%, средняя абсолютная разница 18,5 → 13,7 п.п. Модель независимых ответов не доказывает надёжность реальных грейдов. 27 тестов прошли в Docker, включая покрытие блоков, границы прохождения и старую форму. Контейнер healthy. Через браузер выдана новая форма с 12 заданиями.
HTTP smoke прошёл: подбор, приглашение, принятие, открытие контакта, публикация и редактирование вакансии, отклик и решение, ФСП-мок, PDF, паттерн.
Пересоздание контейнера --force-recreate --wait сохранило созданную вакансию и принятый отклик в именованном томе.
В браузере проверены сохранение изменений вакансии и приглашение кандидата к обсуждению по отклику.

Общий запуск на свободном порту: docker compose up -d --build --wait
Другой порт: PORT=8081 docker compose up -d --build --wait
Тесты: docker compose run --rm --no-deps platform python -m unittest discover -s tests -v
Smoke (только деморежим, создаёт синтетические записи): docker compose exec -T platform python scripts/smoke.py

Проверка относится к конкурсному MVP с моковым ФСП и синтетическими аккаунтами. Реальный SMTP, реальный ФСП API и публичное размещение не проверялись.
